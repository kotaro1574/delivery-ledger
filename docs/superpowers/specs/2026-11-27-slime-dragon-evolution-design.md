# スライムがドラゴンに進化する 設計

## 目的と理由

レトロ RPG 風リデザイン（PR #8）のあと、ユーザーから「スライムのクオリティを上げたい」と相談があった。一番の不満は **成長してもカッコよくならない** こと。

今の作りの問題:

- 体の大きさは同じで、1 レベルごとに装備（星、マフラー、ゴーグル、キラキラ）が 1 個ずつ増えるだけ。シルエットがほとんど変わらない
- 後半は装備が重なってごちゃつく。ゴーグルが目を隠す
- 乗り物の上に浮いているように見え、乗っている感じがしない
- オーラが紺の背景で茶色く濁る（ベージュ時代の半透明の金色が残っている）

そこで、スライムが **レベルが上がるたびに少しずつ形を変え、最後はドラゴンになる** ようにする。毎レベル「お、変わった」が見えることが、レベルを上げる楽しさになる。

ユーザーが決めたこと:

- 方向性は C（体が育つ＋顔がキリッとする＋乗り物を描き直す＋装備を整理）。そのうえで「スライムがだんだんドラゴンになる」
- 乗り物は B: 徒歩 → 自転車 → スクーター → 自分の翼で飛ぶ。ドラゴンは飛んで配達する
- 子ドラゴンは丸く（スライムらしさを残す）、キングドラゴンは派手に
- キラキラや装備を足すのではなく、**毎レベル必ず形が変わる** 段階的な進化にする（下の割り当て表）
- 名前は肩書き（ルーキー等）をやめて生き物の名前にする
- キングドラゴンは炎も吐く

## ゴール

- Lv1〜41 のどのレベルに上がっても、前のレベルと形が違う
- Lv31 でスライムからドラゴンに変わっても、丸っこさが残ってつながって見える
- キングドラゴン（Lv41〜）が一目で「すごい」と分かる
- 紺の背景（`--game-panel` #141a3d / `--game-bg` #0b0f2a）の上でシルエットがはっきり見える

## やらないこと

- レベルの計算方法（目標の 2.5% ごとに 1 レベル、Lv41 でキング）を変えること
- 演出のアニメーションを増やすこと（今の `slime-bob` / `rider-bounce` をそのまま使う）
- ホーム画面のアプリアイコンの作り直し
- 画像ファイル（PNG など）を使うこと。今と同じくコードでドット絵を描く

## 失敗とみなすこと（動いていてもダメなもの）

- 隣り合うレベルで見た目が同じになる
- 顔（目と口）が装備や翼で隠れる
- 紺の背景に溶けて輪郭が分からない部分がある
- 既存のゲームのキャラクターの見た目や名前をまねたもの

## 制約

- Next.js 16 / Tailwind v4 / vitest。描画は今の `slime-sprite.ts`（グリッドに色を置いて、`toRuns` で横に連続する同じ色を 1 つの `rect` にまとめた SVG）の仕組みを使う
- CLAUDE.md のルール: `any` 禁止、説明コメントなし、`useEffect` は極力使わない
- アニメーションは `motion-safe:` の中だけ
- 文言はひらがな中心のゲーム口調（PR #8 のルールを引き継ぐ）

## 検討した作り方

| 案 | 内容 | トレードオフ |
| --- | --- | --- |
| A. 段階ごとに装備を整理 | 体はそのまま、乗り物と装備をきれいに描き直す | 早いが、成長しても形が変わらない不満が残る |
| B. 段階ごとに進化 | 10 レベルごとに体の形が変わり、段階の中はキラキラなどで変化 | 段階の中の変化が「飾り」になり、育っている感じが弱い（ユーザーが指摘） |
| **C. 毎レベル形が変わる進化（採用）** | 部品ごとに「何レベルでどう変わるか」を決め、レベルから全部の形を計算する | 割り当て表の分だけ手間がかかる。そのかわり毎レベル変化が見える |

## デザインの決めごと

### キャンバス

- 32×32 から **48×48** に広げる（画面上の大きさは今と同じ。`viewBox` を `0 0 48 48` にする）
- 輪郭はインク色 `#120e26`。部品ごとに輪郭を付けて、重なりの境目が分かるようにする
- 影は右下が暗くなる 3〜4 段の塗り分け（左上から光が当たる）

### 名前（Lv の横のバッジ）

| レベル | 名前 | 移動 |
| --- | --- | --- |
| Lv1〜10 | はいたつスライム | 徒歩（配達バッグを背負う） |
| Lv11〜20 | ツノスライム | 自転車 |
| Lv21〜30 | ハネスライム | スクーター |
| Lv31〜40 | チビドラゴン | 自分の翼で飛ぶ（配達ボックスを手で持つ） |
| Lv41〜 | キングドラゴン | 金のドラゴンが飛ぶ |

`tierTitles`（ルーキー / レギュラー / エース / ベテラン / キング）はこの 5 つに置き換える。

### 色

- 体の色はレベルごとに少しずつ変える。段階の基準色の間を色相で補間する（緑 → 青 → 紫 → ピンク → 赤 → オレンジ）。
  - 段階の基準色は今の `bodyPalettes` の系統を使う（緑 / 青 / 紫 / オレンジ）
  - キングだけは補間せず、金色に固定する
- 補間は色相の近い側を回る（紫 → オレンジは赤を通る）。RGB で混ぜると濁るので使わない
- 半透明の色は使わない（紺の上で濁る）

### 毎レベルの形の変化（割り当て表）

色は全レベルで変わる。この表は形の変化だけを書く。前のレベルの変化はすべて引き継ぐ。

### 顔

- 目は 2〜3 マスの縦長で、左上に白い光を入れる
- 前半（〜Lv19）は丸い目のかわいい顔。Lv20 から眉が付く。チビドラゴンは Lv38 まで丸い目
- どの段階でも目と口は隠さない

### 乗り物

- 自転車・スクーターは線画ではなく、色と影のある絵にする。タイヤは暗い色＋上側に明るいハイライト（紺の上で輪郭が見えるように）
- スライムはサドル / シートに座らせ、ハンドルを握る手を描く
- スクーター以降は体の後ろにスピード線を出す
- 飛んでいるときは地面に小さな影を出す

### 文言

| 場面 | いま | これから |
| --- | --- | --- |
| レベルアップ | スライムは レベル14に あがった！ | ツノスライムは レベル14に あがった！（上がったあとの名前が入る） |
| 段階が上がる（10 レベルごと） | レギュラーに しんかした！ | はいたつスライムは ツノスライムに しんかした！ |
| キングになる | もくひょうたっせい！ スライムキングが たんじょうした！ | もくひょうたっせい！ キングドラゴンが たんじょうした！ |
| 目標がないときの説明 | もくひょうの 2.5% を かせぐごとに 1レベル。100% で スライムキング | もくひょうの 2.5% を かせぐごとに 1レベル。100% で キングドラゴン |
| 読み上げ用ラベル | Lv.14 レギュラーの はいたつスライム | Lv.14 ツノスライム |
| 目標がないときの見出し / キング回数 / たまご | （そのまま） | もくひょうを きめると スライムが うまれる / キング N回 / スライムのたまご |

段階が上がるレベル（11, 21, 31）では「あがった！」と「しんかした！」の両方が出る（今の動きと同じ）。キングになるときは「しんかした！」の代わりに「たんじょうした！」が出る。

## 作りの方針

- 見た目をレベルから計算する: `composeSlime` の入力を `{ tier, step, gems }` から **レベル（数値）** に変える。各部品の大きさや有無は、割り当て表からレベルで決める
- お試し画像は一時フォルダのスクリプトで描いた使い捨て（消えることがある）。その描き方（部品ごとの輪郭、楕円の塗り分け、多角形の翼、色相の補間）は参考にするが、この設計の割り当て表と決めごとが正
- たまごの絵も 48×48 で描き直す
- `MonthlyLevel` の `step` / `gems` は、見た目をレベルから計算するなら不要になる。消すか残すかは実装者の判断

## 実装者にまかせること

- 部品の正確な座標、サイズ、色の値（紺の上でコントラストが出ること）
- 関数やファイルの分け方
- テストの具体的な書き方。少なくとも次の 3 つは確認する
  - 隣り合うレベル同士でグリッドが違う（Lv1〜41、Lv43、Lv45、Lv49、Lv53）
  - 目のマスが他の部品で上書きされていない
  - 半透明の色を使っていない

## 確認方法

- vitest 全部通る。Biome と typecheck も通る
- Lv1〜53 の全レベルの画像を並べたシートを作り、隣り合うレベルで形の違いが見えることを目で確認する
- Browser pane（375px 幅）でステータス欄のスライムと、レベルアップ・進化・キング誕生のお祝いバナーを確認する
