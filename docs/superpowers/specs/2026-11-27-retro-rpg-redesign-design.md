# レトロ RPG 風リデザイン 設計

## 目的と理由

ステータスパネルの配達スライムはドット絵のゲームキャラなのに、アプリの残りは「紙の台帳」テーマ（ベージュの紙・インク黒・ゴールド）のままで、世界観が 2 つ混ざっている。スライムに合わせてアプリ全体をゲーム画面っぽくし、開いた瞬間から「レベル上げをしている」気分で配達の記録をつけられるようにする。

ユーザーが決めたこと:

- 見た目は 3 案のモックアップのうち **A. レトロ RPG 風**（紺の背景、白い枠のウィンドウ、ドット文字、▶ カーソルのメニュー）
- 作り方は **案 2**（テーマ差し替え + 共通のゲームウィンドウ部品 + 全画面の作り直し）
- 画面の文言は **ひらがな中心のゲーム口調** にする

## ゴール

- ログイン / 新規登録 / 月の台帳 / 入力 / 年間 の全画面が同じレトロ RPG の世界観になる
- 共通部品（ウィンドウ、ボタン、コマンドメニュー）を作り、画面ごとに見た目がバラバラにならない
- 配達の合間でも金額がパッと読める

## やらないこと

- 機能・データ・API の変更（見た目と文言だけ）
- ホーム画面のアプリアイコン（`app/icon.tsx`, `apple-icon.tsx`, `app/icons/[name]`）の作り直し → 後で別にやる
- ライト / ダークの切り替え。常に紺の画面 1 種類
- 効果音、BGM

## 失敗とみなすこと（動いていてもダメなもの）

- 金額や日付が読みにくくなる（ドット文字で小さい数字がつぶれる等）
- 会計用語が変わる。経費カテゴリ名（勘定科目）、仕訳プレビュー、「青色申告」まわりの表記はひらがなにしない
- 配達中にタップしにくくなる（タップ領域は今より小さくしない）

## 制約

- Next.js 16 App Router、Tailwind v4、shadcn。既存のトークン経由の書き方（`globals.css` の CSS 変数）を活かす
- CLAUDE.md のルール: `any` 禁止、説明コメントなし、`useEffect` は極力使わない、ライブラリの API は実装前に context7 で確認
- フォント読み込みは `next/font/google` を使う（実装前に context7 で Next.js 16 の使い方を確認する）
- 既存テストの文言を使ったクエリは、新しい文言に合わせて更新する。テストの意図は変えない
- アニメーションは今と同じく `motion-safe:` の中だけで使う

## 検討した作り方

| 案 | 内容 | トレードオフ |
| --- | --- | --- |
| 1. テーマ差し替えだけ | 色とフォントを置き換え、直書きの色をトークン化 | 早いが、レイアウトはカード型の台帳のまま。白い枠のウィンドウや ▶ メニューの RPG らしさが出ない |
| **2. テーマ + 共通部品 + 全画面の作り直し（採用）** | 1 に加え、ゲームウィンドウ・ボタン・コマンドメニューを作り、4 画面を組み直す | 手間は最大だが、モックアップ A どおりになり、どの画面でも世界観が続く |
| 3. ステータスとメニューだけ作り直す | 一覧や入力フォームは色の差し替えだけ | 入力画面や年間画面で「色が変わっただけの台帳」に戻り、世界観が途切れる |

ユーザーは案 2 を選んだ。理由は、A を選んだ動機がスライムとの統一感で、画面は 4 つしかないから。

## デザインの決めごと

### 色（実装時にトークンへ。印のないものは実装者の判断）

| 役割 | 値 | 備考 |
| --- | --- | --- |
| 背景 / ウィンドウの中 | `#0b0f2a`（紺） | 背景のドット柄は消す |
| ウィンドウの枠・本文 | `#ffffff` | |
| サブテキスト | `#aab0c8` 程度 | 紺の上で WCAG AA を満たす値にする |
| 強調・カーソル・選択中 | `#ffd84a`（黄） | ▶ カーソル、レベル表示、選択中のメニュー |
| 収入 | `#4ad66d`（緑） | |
| 経費 | `#ff6b6b`（赤） | |
| 土曜 / 日曜 | 紺の上で読める青 / 赤 | 実装者の判断 |

`themeColor` も紺にする。既存の `--ledger-*` は新しい名前のトークンに置き換え、`#fffdf7` などの直書きはなくす。スライムのスプライトの色はそのまま。

### 文字

- 見出し、メニュー、ラベル、ボタン、本文: **DotGothic16**（Google Fonts）
- 金額、日付、時給などの数字: 読みやすい等幅フォント（今の `--font-mono` の系統）。ドット文字にはしない
- 入力欄の中身: 等幅フォント（数字が主なので）
- 最小サイズはドット文字で 12px。小さい文字は増やさない

### 共通部品（`app/src/components/game/` に置く。実装者の判断）

- **GameWindow**: 白い 3px の枠に紺の外側の線を重ねた「ドラクエ風」の二重枠ウィンドウ。角は少しだけ丸める（約 4px）。見出し（ウィンドウの名前）を枠の上辺に重ねて置けるようにする
- **ゲームボタン**: 白い枠のボタン。主要ボタンは黄色で目立たせる。フォーカス / ホバー時に左へ ▶ を出す。shadcn の `Button` の variant として足すか、ラップするかは実装者の判断
- **コマンドメニュー（ナビ）**: 今のヘッダーのタブを、コマンドウィンドウ風に置き換える。今いる画面の項目に ▶ と黄色を付ける。項目は「だいちょう」「ねんかん」「きろくする」。ログアウトもメニュー内に置く
- **メッセージウィンドウ**: お祝いバナーや toast を RPG のメッセージ欄のように見せる

既存の shadcn 部品（Card, Input, Popover, Calendar, Tabs, Sonner など）は、トークンの差し替えとクラス調整で RPG 風にする。新しいライブラリは入れない。

### 画面ごと

- **ログイン / 新規登録**: 中央に GameWindow。タイトルは「ぼうけんの きろく」のようなゲームのタイトル画面風。ボタンは「ログイン」→「はじめる」など
- **月の台帳**: 上から ステータスウィンドウ（スライム + Lv + EXP バー）→ 月の切り替え → 日ごとの推移 → 取引一覧、の順はそのまま。それぞれ GameWindow に入れる
  - 達成率バーは「EXP」と表示
  - 「¥186,000 稼いだ」→「かせいだ ¥186,000」
  - 「次のLvまで」→「つぎのレベルまで」
- **入力**: フォーム全体を GameWindow に入れ、収入 / 経費の切り替えはコマンド選択風（▶ 付き）にする
- **年間**: 月ごとの表とグラフを GameWindow に入れる。グラフは手描き SVG のままで、色だけ新しいトークンにする
- **お祝いバナー**: メッセージウィンドウにする
  - 「スライムは レベル26に あがった！」
  - 進化した: 「ベテランに しんかした！」
  - キング: 「もくひょうたっせい！ スライムキングが たんじょうした！」

### 文言のルール

- ひらがな中心のゲーム口調。分かち書き（単語の間の半角スペース）は、メッセージウィンドウの文だけに使う
- ひらがなにしないもの: 会計用語（勘定科目、仕訳、青色申告）、「レシート」などカタカナ語、数字と単位（¥, 円, 時間）、エラーの原因を説明する部分の名詞（メールアドレス、パスワード）
- 対応表の例（表にない文言は、このルールで実装者が決める）

| いま | これから |
| --- | --- |
| 台帳 / 年次 / 入力 | だいちょう / ねんかん / きろくする |
| 配達収支台帳（アプリ名の見出し） | はいたつ しゅうし だいちょう |
| 売上 / 収入 / 経費 | うりあげ / しゅうにゅう / けいひ |
| 保存した / 保存に失敗した | セーブした！ / セーブできなかった… |
| 削除した / 取引を削除 | けした / とりひきを けす |
| 更新した | かきかえた！ |
| 前の月 / 次の月 | まえの つき / つぎの つき |
| 目標金額 / 今月の目標を決めよう | もくひょうきんがく / こんげつの もくひょうを きめよう |
| 閉じる | とじる |

- `aria-label` も見た目の文言に合わせて変える。ブラウザのタブのタイトル（metadata）と PWA 名はいまのまま

## 実装者にまかせること

- 部品の props の形、ファイル分け
- 細かい余白、枠の太さ、文字サイズの調整（モックアップ A に寄せる）
- 対応表にない文言（上のルールに従う）
- 土日の色、サブテキストの色の正確な値（コントラストを満たすこと）

## 確認方法

- vitest 全部通る（文言の変更に合わせてテストを更新）
- Biome / typecheck が通る
- Browser pane で 375px 幅のスマホ表示を確認する。ログイン、月の台帳（目標あり / なし / レベルアップ演出）、入力（収入・経費）、年間の各画面
